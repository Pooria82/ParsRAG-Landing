> خلاصهٔ فارسی سیاست امنیتی. متن کامل انگلیسی پایین‌تر آمده است.

### نسخه‌های پشتیبانی‌شده
نسخه‌های ‎1.0.x پشتیبانی می‌شوند؛ ‎0.2.x و نسخه‌های قدیمی‌تر نه.

### گزارش آسیب‌پذیری
از مسیر **Report a vulnerability** در بخش Security مخزن گیت‌هاب استفاده کنید و برای افشای اطلاعات ورود، نشت داده یا هر یافتهٔ قابل‌سوءاستفاده‌ای issue عمومی باز نکنید. نسخهٔ آسیب‌دیده، شیوهٔ استقرار، مراحل بازتولید، اثر و راه‌حل پیشنهادی را بنویسید و کلیدهای واقعی و اسناد محرمانه را از گزارش حذف کنید. نگه‌دارندگان قرار است ظرف هفت روز دریافت گزارش را تأیید کنند.

### مرز امنیتی
پارس‌رگ برای یک کاربر روی یک رایانه طراحی شده است. قراردادن آن روی شبکهٔ مشترک یا نامطمئن بدون reverse proxy دارای احراز هویت، بیرون از مرز پشتیبانی‌شده است.

API فقط به نام‌های میزبان محلی (localhost، 127.0.0.1 و ::1) پاسخ می‌دهد، مگر آنکه PARSRAG_ALLOWED_HOSTS نام‌های دیگری اضافه کند؛ این جلوی DNS rebinding را می‌گیرد. درخواست‌هایی که وضعیت را تغییر می‌دهند باید از مبدأ خود برنامه یا مبدأهای مجاز بیایند.

### استثناهای مستندشده
یک آسیب‌پذیری غیرمستقیم در NLTK که پارس‌رگ از بخش آسیب‌پذیرش استفاده نمی‌کند، در بررسی خودکار نادیده گرفته می‌شود. بررسی image فقط یافته‌های جدی و بحرانیِ دارای راه‌حل را مانع انتشار می‌داند. پروفایل AMD هنوز از PyTorch 2.6 استفاده می‌کند و هشدارهای آن پیش از استقرار باید بررسی شوند.

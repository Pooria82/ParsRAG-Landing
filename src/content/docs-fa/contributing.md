> خلاصهٔ فارسی راهنمای مشارکت. متن کامل انگلیسی پایین‌تر آمده است.

- کار را از شاخهٔ `develop` شروع کنید، commitها را متمرکز نگه دارید و از قالب Conventional Commits استفاده کنید.
- هرگز فایل `.env`، کلیدهای API، دادهٔ ایندکس‌شده، وزن مدل‌ها یا اسناد خصوصی را commit نکنید.
- مشارکت فقط از راه Pull Request به مخزن رسمی پذیرفته می‌شود. با ارسال آن تأیید می‌کنید مالک آن هستید و توافق مشارکت‌کنندگان را می‌پذیرید. صاحب پروژه همهٔ تغییرها را بازبینی می‌کند.
- تا وقتی Pull Request در حال بازبینی است، انتشار، استقرار یا توزیع نسخهٔ تغییریافته مجاز نیست.
- پیش از ارسال، بررسی‌های محلی را اجرا کنید: قالب‌بندی و بررسی کد با Ruff، mypy سخت‌گیرانه، pytest با پوشش، آزمون سرتاسری و آزمون‌ها و ساخت فرانت‌اند.
- هر تغییر رفتاری به آزمون قطعی نیاز دارد. ارزیابی با مدل زبانی زنده باید جدا انجام شود و مدل، نسخهٔ داده، پیکربندی و تاریخ را مشخص کند.
